# codemap — agent instructions

This repository **is the codemap tool**: it builds and incrementally maintains an
interactive architecture map + per-module code-quality audit for any codebase. It is a
Claude Code skill, but the engine is tool-agnostic — **Codex, Cursor, Aider, or any
agent that can read instructions and spawn sub-tasks can drive it.**

## Read these first
- **`reference/MAINTAINABILITY.md`** — coverage, evidence and acceptance protocol.
- **`SKILL.md`** — the full workflow and the `init / check / update / test / fix`
  commands. Follow it exactly.
- **`reference/STANDARDS.md`** — the fixed scoring rubric, smell taxonomy (with
  per-language equivalents), severity levels, and the **exact per-module audit prompt**.
- **`reference/QUALITY_GATES.md`** — the long-term code-quality, verification, tooling,
  security/performance and change-safety gates required before an enabled project can
  publish a retained audit.
- **`reference/DATA_MODEL.md`** — the `modules.json` schema (the source of truth).

## Non-negotiable rules
1. **`modules.json` is the source of truth.** The HTML and MD are generated by
   `scripts/render.py` — never hand-edit them. Manual state edits are limited to
   decomposition/structure (`id`, `paths`, bands, dependencies and descriptions);
   scores, grades, tags, findings and `audited*` fields must be committed through
   `apply_audit.py` and its shared semantic contract.
2. **Every scored module needs its own evidence-backed assessment.** Follow
   `reference/MAINTAINABILITY.md` for coverage and `reference/STANDARDS.md` for the
   rubric. Prefer authorized independent review; otherwise disclose `single-reviewer`.
   Triage is unscored. Honor user model settings; never reuse scores across modules.
3. For `fix`, prove the original problem is resolved, required behavior is preserved
   and the maintenance scenario benefits. Local fixes may use disclosed self-review;
   high-risk fixes require independent acceptance or remain pending. Relevant new tests
   and expected pre-fix reproductions are part of verification.
4. At an explicit architecture request, milestone, or high-impact boundary that focused
   checks cannot safely cover, retain the completed website/game audit as an immutable
   `<project>/.codemap/versions/audit-vNNNN/` version. The first retained audit is full;
   later ones are incremental or expanded-incremental. Ordinary local changes do not
   trigger audits; no-delta reviews do not allocate versions. Never overwrite an older version,
   and never let `.codemap/` become part of the audited source set.
5. **Hash validity is not semantic validity.** `apply_audit.py`, publish preflight and
   retained-history verification use the same `AuditContract`. New versions carry a
   `semantic-receipt.json`; `version.py verify` must pass both integrity and semantics.
6. Retained v1 histories without a semantic receipt are read-only `legacy-contract`
   records. Verify their meaning independently, but never rewrite them in place.

## The scripts (deterministic, Python 3 stdlib, no install)
```
python scripts/scan.py       --root <proj> --state <state> [--write]   # LoC + hash + staleness
python scripts/query.py      --state <state> --max-grade C --format ids # pick targets cheaply
python scripts/apply_audit.py --state <state> --id <id> --json '<result>'
python scripts/render.py     --state <state> --template assets/template.html \
                             --out-html <html> --out-md <md>
python scripts/version.py    status|publish|verify|rollback --root <proj>
```
`scripts/audit_contract.py` owns the shared semantic rules and
`scripts/audit_state.py` owns validated atomic state writes; callers must not duplicate
their rules or bypass their write boundary.
Use `query.py` (`--format ids|paths|findings`) to target work without reading the whole
`modules.json`. Only scoring / fixing / test-writing need the model; everything else is
a plain script call.
