# Plus 云端服务架构

## 目标

让用户通过邀请码使用 Plus，而不下载 Plus Skill，也不上传项目源码。免费仓库中的连接器只负责传输摘要和调用用户本机 Agent。

## 模块关系

```text
本机 modules.json
  -> plus_client.py（白名单摘要、项目哈希）
  -> Cloudflare Worker（授权、摘要、任务编排）
       -> D1（邀请码、会话、摘要、任务和事件）
  <- 本机 Agent（读取本地源码、生成并应用修复）
```

## 状态所有权

| 状态 | 唯一所有者 | 允许写入者 | 约束 |
| --- | --- | --- | --- |
| 邀请码与次数 | Worker + D1 | 管理员接口 | 只返回明文邀请码一次，数据库只存哈希 |
| Plus 会话 | Worker + D1 | 邀请兑换接口 | 签名令牌过期后不可用，可撤销 |
| 审计摘要 | Worker + D1 | 已授权客户端 | 只接受白名单字段，不接受源码字段 |
| 修复任务与进度 | Worker + D1 | 任务创建和本机事件接口 | 任务归属会话，状态可追踪 |
| 源码与补丁 | 用户本机 Agent | 用户本地工作区 | 永不发送到 Worker |

## 主流程

1. 管理员用 `x-admin-token` 创建邀请码，Worker 只在响应中返回一次明文。
2. 用户客户端兑换邀请码，Worker 创建短期会话令牌。
3. 客户端从本机 `modules.json` 生成白名单摘要并上传；服务端记录 `sourceUploaded=false`。
4. 用户选择方案，Worker 根据摘要生成依赖顺序任务列表。
5. 客户端逐项调用本机 Agent；Agent 在本地读取源码、修复并运行验证。
6. 客户端只回传 `planning/repairing/completed/failed` 等状态和退出码。

## 关键取舍

- 不上传源码意味着云端不能生成精确 diff；补丁必须由本机 Agent 生成和应用。
- Plus 核心只部署在私有 Worker 源码环境；客户端公开发布也不会包含核心 Skill。
- Worker 不直接运行 AI，避免把模型密钥和长任务执行放进免费 Worker；AI 由用户自己的 Agent 执行。
- D1 只保存必要审计摘要和状态；源码内容、路径和凭据不进入请求协议。

## 完成标准

- 未授权请求不能创建摘要或任务。
- 过期、用尽或撤销的邀请码不能兑换。
- 摘要请求不含源码、文件内容、差异或凭据字段。
- 用户可查询任务状态，单个模块失败后任务停止并保留失败事件。
- Plus Skill 不出现在公开免费仓库的客户端代码中。
